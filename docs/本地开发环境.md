## 3. 已知偏差：MySQL 版本

**本机运行 MySQL 9.6.0，规划文档与生产目标是 MySQL 8.4 LTS。** 二者存在实质差异：

| 差异点 | 影响 |
|---|---|
| 发布策略 | 9.x 是 Innovation 快速迭代版，8.4 是 LTS。9.x 的特性可能不回移到 8.4 |
| 废弃特性移除 | 9.x 移除了 8.4 中仅标记废弃的语法，迁移 SQL 若用到会在 8.4 上报错或反之 |
| 默认值 | `sql_mode`、字符集默认值、认证插件在版本间有调整 |
| 优化器行为 | 执行计划可能不同，性能结论不可直接套用 |

**应对策略：**

1. **迁移 SQL 保持保守**：只用两版都支持的语法，不碰 9.x 新增函数与 JSON 增强。
2. **CI 用 `mysql:8.4` 校验**：`docker-compose.yml` 固定 `mysql:8.4`，CI 跑迁移与集成测试时能提前暴露版本不兼容。
3. **上线前全量回归**：Phase 5 生产化时，在 8.4 环境完整跑一遍迁移与核心链路。

> 如后续希望本地也用 8.4，可执行 `brew install mysql@8.4` 并让其监听 3307 端口，与现有 9.6 实例并存。届时只需改 `.env` 的 `MYSQL_DSN` 端口。

## 4. 环境变量

```bash
cp .env.example .env    # 首次使用
```

`.env` 已被 `.gitignore` 忽略。变量分组与硬约束：

| 分组 | 变量 | 约束 |
|---|---|---|
| 应用 | `APP_ENV` `APP_PORT` `APP_BASE_URL` | — |
| MySQL | `MYSQL_DSN` `MYSQL_TEST_DSN` | Go 驱动 DSN 格式 |
| Redis | `REDIS_ADDR` `REDIS_PASSWORD` `REDIS_DB` | `REDIS_DB` 必须为 1 |
| 认证 | `JWT_SECRET` `JWT_ACCESS_TTL` `JWT_REFRESH_TTL` | 生产环境必须替换 |
| FoxSSL | `FOXSSL_BASE_URL` `FOXSSL_API_KEY` `FOXSSL_WEBHOOK_SECRET` | **仅服务端**，禁止进入前端产物与日志 |
| 支付 | `PAYMENT_PROVIDER` `PAYMENT_APP_ID` `PAYMENT_PRIVATE_KEY` `PAYMENT_WEBHOOK_SECRET` | 同上 |
| 邮件 | `SMTP_HOST` `SMTP_PORT` `SMTP_USER` `SMTP_PASSWORD` | 本地用 Mailpit（1025） |
| 日志 | `LOG_LEVEL` | 本地 `debug` |

本地开发 `FOXSSL_API_KEY` 与 `PAYMENT_PRIVATE_KEY` 留空，走 `mock_client.go`。`make env-check` 会在检测到这些变量非空时告警。

## 7. 故障排查

| 现象 | 原因与处理 |
|---|---|
| `make env-check` 报 MySQL 连接失败 | 确认 Homebrew MySQL 已启动：`brew services list`，或 `mysql -h 127.0.0.1 -u root -proot -e "SELECT 1"` |
| Redis 报错 `NOAUTH` | 本机 Redis 无口令，确认 `.env` 的 `REDIS_PASSWORD` 为空 |
| 数据串到其他项目 | 检查 `.env` 的 `REDIS_DB` 是否为 1；db0 属于其他项目 |
| `migrate: command not found` | `~/go/bin` 未在 PATH。执行 `go install -tags 'mysql' github.com/golang-migrate/migrate/v4/cmd/migrate@latest` |
| 迁移状态脏（dirty） | `make migrate-force version=<上一个正常版本>` 后重新 `migrate-up` |
| 端口 3306 被占用 | 本机 MySQL 与其他服务冲突，`lsof -nP -iTCP:3306 -sTCP:LISTEN` 查占用进程 |
| 前端起不来，报 `EADDRINUSE :::3000` | 本机 3000 端口已被其它项目占用。用户站换端口启动：`pnpm --filter web exec next dev -p 3001`。注意 `pnpm run dev -- -p 3001` 会把 `--` 原样透传给 Next，必须用 `exec` 直调 |
| 后台起不来，报 8000 被占用 | 同理换端口：`pnpm --filter admin exec umi dev --port 8001` |
| `yarn` / `pnpm` 安装报 `CODEBUDDY_BROKER_DENY` | 沙箱通过 `NODE_OPTIONS` 注入的 fs shim 只支持递归 `mkdir`。所有 Node 包管理命令前加 `env -u NODE_OPTIONS` |

### 7.1 端口约定

| 服务 | 端口 | 说明 |
|---|---|---|
| Go API | 8080 | 两个前端的 `/api` 都代理到这里 |
| 运营后台 | 8000 | Umi 默认 |
| 用户站 | 3000 | Next.js 默认；本机可能与其它项目冲突，见上表 |

前端的 `/api` 代理在 `apps/*/` 的配置里声明（`.umirc.ts` 的 `proxy`、`next.config.ts` 的
`rewrites`），生产环境由 nginx 承担同样职责。
